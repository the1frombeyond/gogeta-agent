## Key Violation Patterns

### 1. Tools importing `gogeta_cli.config` (L1 → L8) — 318 layer violations
The single largest violation class. Many tools read config values via `gogeta_cli.config`.
This is a design tension: tools need config, but config lives in the CLI layer.

**Fix:** Extract config-reading utilities to `tools/` layer, or pass config through the
registration/handler callback chain.

### 2. Tools importing Agent Core (L1 → L4) — 84 prohibited violations
Tools commonly import `agent.auxiliary_client`, `agent.redact`, `agent.async_utils`,
`agent.skill_utils`, `agent.file_safety`, agent registries.

**Fix:** Extract shared utilities (redact, async_utils) to `utils.py` or a `tools/shared` module.
Move skill_utils to `tools/skills/` or extract to lower layer.

### 3. Gateway importing Tools directly (L7 → L1) — 73 prohibited violations
`gateway/run.py` is the worst offender (~40 direct tool imports).
Platform files import `tools.url_safety`, `tools.approval`, `tools.lazy_deps`.

**Fix:** Gateway→agent→tools chain. Gateway needed tool access should go through agent
methods, or refactor tool functionality into gateway utilities.

### 4. Tools importing Gateway (L1 → L7) — 59 prohibited violations
`tools/send_message_tool.py` is the primary offender, importing gateway platforms and
session context. `tools/approval.py` imports `gateway.session_context`.

**Fix:** Break `gateway.session_context` into a shared type in `gogeta_state`.
`send_message_tool.py` should use a gateway bridge, not direct imports.

### 5. Agent Core importing Gateway (L4 → L7) — 6 prohibited violations
`agent/agent_init.py`, `agent/conversation_compression.py`, `agent/prompt_builder.py`,
`agent/skill_commands.py`, `agent/skill_utils.py`, `agent/system_prompt.py` all import
`gateway.session_context` or `gateway.platform_registry`.

**Fix:** Move session context to shared layer, remove platform_registry dependency from
system prompt builder.

## Scope Note
- Tests (`tests/`), skills (`skills/`, `optional-skills/`), and UI (`ui-tui/`, `website/`, `apps/`) are excluded from scanning
- Lazy imports between allowed layers (agent→plugin, orchestration→agent) are permitted
